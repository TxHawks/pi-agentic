## Evidence grades

- **Promised:** README or a public tool description states the behavior.
- **Tested:** A repository test asserts the behavior. Tests use fake processes unless noted.
- **Implementation-only:** The source implements the behavior without a user promise or live proof.

- **Missing:** The repository does not define or test the behavior.

## Launch and session contract

- **Promised and implementation-backed:** A named agent owns mode, wait policy, session mode, lifecycle, timeout, and parent-close policy. The tool call supplies the agent, task, name, and title. [README.md, “The model” and “Frontmatter reference”](../../README.md#the-model); [src/tools/subagent-tools.ts#L44-L75](../../src/tools/subagent-tools.ts#L44-L75); [src/launch/policy.ts#L23-L45](../../src/launch/policy.ts#L23-L45).
- **Promised:** `background` starts headless `pi -p`. `interactive` uses a detected Herdr, cmux, tmux, zellij, or WezTerm surface. If no supported mux is active, interactive launch fails with a setup hint. [README.md, “The model” and “Interactive mux backends”](../../README.md#the-model); [src/mux/core.ts#L7-L75](../../src/mux/core.ts#L7-L75).
- **Implementation-only:** Background launch uses `spawn()` with `detached: true`, calls `unref()`, and starts in the effective child cwd. It ignores stdin. It pipes stdout and stderr for `terminate`, but ignores both for `continue`. It stores only the last 4,000 characters of each pipe. [src/launch/background.ts#L107-L145](../../src/launch/background.ts#L107-L145).
- **Promised and tested:** Default session mode is `lineage-only`. `standalone` has no parent link. `fork` copies parent context. A lineage child keeps lineage but starts clean. [README.md, “Session modes”](../../README.md#session-modes); [src/session/session-files.ts#L373-L380](../../src/session/session-files.ts#L373-L380); [test/session/session-mode.test.ts](../../test/session/session-mode.test.ts).
- **Promised and implementation-backed:** A non-standalone child requires a parent session file. The launch fails and tells the caller to use `standalone` or a persistent parent session when that file is absent. [src/launch/seed-child-session.ts#L38-L57](../../src/launch/seed-child-session.ts#L38-L57).
- **Promised:** `no-session: true` uses a temporary session file and deletes it after completion. For lineage or fork, the temporary file still receives inherited context. It is not suitable for resume or durable caller ping. [README.md, “`no-session: true`”](../../README.md#no-session-true); [src/launch/seed-child-session.ts#L8-L19](../../src/launch/seed-child-session.ts#L8-L19); [src/runtime/background-watch.ts#L58-L63](../../src/runtime/background-watch.ts#L58-L63).
- **Implementation-only:** The child writes launch metadata and an extension companion file. Resume depends on these files. Missing or malformed extension metadata falls back to no extensions. [src/session/session-files.ts#L356-L370](../../src/session/session-files.ts#L356-L370); [src/session/session-files.ts#L279-L318](../../src/session/session-files.ts#L279-L318).

## Sync, async, mixed batches, and delivery

- **Promised:** `async: true` returns a started result. The final child message returns later by steer. `async: false` waits and returns the child result in the tool result. [README.md, “Launching and waiting”](../../README.md#launching-and-waiting); [src/runtime/running-registry.ts#L143-L181](../../src/runtime/running-registry.ts#L143-L181).
- **Promised and tested:** A batch with at least one blocking child is a barrier. All children launch. The parent waits for all results, including async children. A pure async child-only batch stays detached. An async child mixed with another tool is marked blocking unless the coordinator-only guard is disabled. [README.md, “Mixed sync and async batches”](../../README.md#mixed-sync-and-async-batches); [test/runtime/mixed-batch-classifier.test.ts#L46-L167](../../test/runtime/mixed-batch-classifier.test.ts#L46-L167).
- **Promised:** The default coordinator-only guard may end the parent turn after an async launch. `PI_SUBAGENT_DISABLE_COORDINATOR_ONLY_TURN=1` permits independent parent work. [README.md, “Launching and waiting”](../../README.md#launching-and-waiting); [src/runtime/state.ts#L116-L147](../../src/runtime/state.ts#L116-L147).
- **Promised and tested:** Detached completion is sent as a steer message. A later wait can use the cached result. A wait timeout with `onTimeout: detach` returns `pending` and restores steer delivery. A normal timeout returns an error. An interrupted wait stops the child. [src/runtime/running-registry.ts#L212-L267](../../src/runtime/running-registry.ts#L212-L267); [test/runtime/wait.test.ts#L83-L220](../../test/runtime/wait.test.ts#L83-L220).
- **Promised:** `subagent_resume` uses the saved launch metadata and preserves the original launch shape. It accepts a follow-up task. The tool usually returns after starting the child. [README.md, “Resuming child sessions”](../../README.md#resuming-child-sessions); [src/tools/resume-tool.ts#L35-L93](../../src/tools/resume-tool.ts#L35-L93).
- **Implementation-only:** A resume rejects a duplicate running session. Resume of a missing, temporary, or damaged session is not defined by a compatibility test. [src/runtime/resume-service.ts#L209-L239](../../src/runtime/resume-service.ts#L209-L239); [test/runtime/resume-tool.test.ts](../../test/runtime/resume-tool.test.ts).

## Lifecycle, timeout, stop, and output

- **Promised:** `auto-exit: true` closes a child after normal completion. Manual background children must call `subagent_done`; `caller_ping` asks the parent for help and leaves a resumable session. [README.md, “Child lifecycle”](../../README.md#child-lifecycle); [src/tools/subagent-done.ts#L396-L430](../../src/tools/subagent-done.ts#L396-L430).
- **Implementation-only:** The child extension writes a sidecar on shutdown. It records done, ping, output tokens, and provider errors. The watcher prefers that sidecar exit data over the process exit code. [src/tools/subagent-done.ts#L286-L322](../../src/tools/subagent-done.ts#L286-L322); [src/runtime/background-watch.ts#L100-L107](../../src/runtime/background-watch.ts#L100-L107).
- **Promised and implementation-backed:** Agent timeout sends `SIGTERM` to the child process group. Watcher abort sends `SIGTERM`, then `SIGKILL` after five seconds if the child is still present. [README.md, “Frontmatter reference” (`timeout`)](../../README.md#frontmatter-reference); [src/runtime/background-watch.ts#L44-L47](../../src/runtime/background-watch.ts#L44-L47); [src/runtime/background-watch.ts#L94-L99](../../src/runtime/background-watch.ts#L94-L99).
- **Promised:** `subagent_kill` stops either mode. [README.md, “Child lifecycle”](../../README.md#child-lifecycle); [src/tools/subagent-tools.ts#L374-L389](../../src/tools/subagent-tools.ts#L374-L389); [src/runtime/running-registry.ts#L112-L141](../../src/runtime/running-registry.ts#L112-L141).
- **Implementation-only output precedence:** For a persistent session, the watcher selects the last child assistant text, then the last non-protocol tool result. If none exists, it uses non-zero stderr, zero-exit stdout, or a zero-exit no-output message. For `no-session`, it cannot read session output, so it uses stdout, then non-zero stderr, otherwise the generic runtime summary. [src/runtime/background-watch.ts#L108-L133](../../src/runtime/background-watch.ts#L108-L133); [src/session/session.ts#L103-L149](../../src/session/session.ts#L103-L149).
- **Tested:** Provider errors preserve real last output as incomplete output. Runtime-only fallback output is not treated as a child result. [test/runtime/wait.test.ts#L36-L67](../../test/runtime/wait.test.ts#L36-L67). Provider recovery and tool-boundary recovery are implementation behavior, not a stable provider compatibility promise. [src/tools/provider-error-recovery.ts](../../src/tools/provider-error-recovery.ts); [src/tools/subagent-done.ts#L365-L430](../../src/tools/subagent-done.ts#L365-L430).

## Parent close and crash behavior

- **Promised and tested:** `terminate` is the default. On normal parent shutdown it stops background children and closes interactive surfaces. `continue` leaves the child running. It disables result delivery to the closed parent, clears ownership, and leaves the session file. [README.md, “Parent shutdown policy”](../../README.md#parent-shutdown-policy); [src/runtime/shutdown.ts#L62-L107](../../src/runtime/shutdown.ts#L62-L107); [test/runtime/shutdown-policy.test.ts#L61-L139](../../test/runtime/shutdown-policy.test.ts#L61-L139).
- **Implementation-only:** Termination targets the negative child PID first, so it assumes `detached: true` created a usable process group. It falls back to `child.kill(signal)`. Parent shutdown uses a five-second escalation default only when no abort controller exists; the normal watcher abort path has its own five-second escalation. [src/runtime/shutdown.ts#L21-L49](../../src/runtime/shutdown.ts#L21-L49); [src/runtime/background-watch.ts#L94-L99](../../src/runtime/background-watch.ts#L94-L99).
- **Accidental or missing:** A hard parent crash, power loss, `SIGKILL`, or host restart does not run the parent shutdown hook. The source and tests cover orderly shutdown only. Therefore `terminate` is not a hard crash containment guarantee. `continue` stdout and stderr are intentionally discarded, and no result can be delivered to the closed parent. [src/launch/background.ts#L108-L116](../../src/launch/background.ts#L108-L116); [src/runtime/shutdown.ts#L77-L106](../../src/runtime/shutdown.ts#L77-L106); [test/runtime/shutdown-policy.test.ts#L117-L139](../../test/runtime/shutdown-policy.test.ts#L117-L139).

## Host, process, signal, and filesystem contract

- **Promised host surface:** The README names macOS terminal backends through Herdr, cmux, tmux, zellij, and WezTerm. It does not name a minimum macOS or Linux release. [README.md, “Interactive mux backends”](../../README.md#interactive-mux-backends).
- **Implementation-only platform behavior:** Command discovery uses `command -v` on non-Windows hosts and `where.exe` first on Windows. Background process-group signals use POSIX-style negative PIDs. The code has no explicit `darwin` or `linux` version check. [src/mux/runtime-probe.ts#L36-L54](../../src/mux/runtime-probe.ts#L36-L54); [src/runtime/background-watch.ts#L13-L23](../../src/runtime/background-watch.ts#L13-L23).
- **Missing minimum guarantee:** No source, test, or package field states a minimum Node version, macOS version, Linux distribution, kernel, shell, or mux version. The package declares Pi peer versions `@earendil-works/pi-coding-agent >=0.79.10`, `pi-ai >=0.79.0`, `pi-tui >=0.79.0`, and any `typebox`; dev dependencies currently use `0.83.x`. [package.json#L24-L43](../../package.json#L24-L43). The active worktree changes dev dependencies to `0.84.x`, removes and then restores peer metadata ordering, and changes package identity; those files were not part of this branch. [effective `/Volumes/code/pi-agentic/feat-better-bg-subagents/package.json` diff, read-only observation].
- **Filesystem assumptions:** The child needs a writable session directory, a writable artifact root, a resolvable Pi command or executable, and a valid child cwd. Fork and lineage need a readable persistent parent session. `no-session` cleanup removes the temporary session after completion. Exact permissions, network filesystems, symlinks, path length, and crash-recovery rules are missing. [src/launch/background.ts#L107-L115](../../src/launch/background.ts#L107-L115); [src/launch/seed-child-session.ts#L41-L57](../../src/launch/seed-child-session.ts#L41-L57); [src/runtime/background-watch.ts#L58-L63](../../src/runtime/background-watch.ts#L58-L63).
- **Direct observation:** This research host is `Darwin ... arm64` with Node `v26.3.1`. This is one macOS observation only. It is not evidence for a minimum release or Linux support.
- **Minimum practical conclusion:** macOS and Linux are plausible targets when Node, the Pi peer contract, a writable filesystem, and the selected command or mux are present. The repository proves no minimum macOS/Linux version and gives no tested Windows background contract. Treat Windows as unsupported for strict compatibility until process-group and mux behavior are specified and tested.

## Compatibility gaps to resolve before redesign

1. Define a real minimum Node, macOS, Linux, and mux version matrix.
2. Specify whether `terminate` must survive hard parent crash and how orphaned groups are reaped.
3. Specify process-group behavior on Windows or state that Windows is unsupported.
4. Add live tests for detached launch, timeout, stop, parent close, parent crash, stdout/stderr, and session cleanup. The current package test script runs unit suites only; live scripts require explicit opt-in. [package.json#L13-L23](../../package.json#L13-L23); [README.md, “Live tests”](../../README.md#live-tests).
5. Specify output precedence as a public rule, including partial output, provider errors, no-session output, and child protocol messages.
6. Specify artifact and session roots, permissions, atomicity, and recovery after interrupted writes.
7. Keep the `continue` rule explicit: a child may finish, but its closed parent receives no steer result and ignored stdio cannot be recovered by the parent.
